# i18n — localization & translation

`i18n` is the internationalization SDK: strongly-typed, Rust-native
translations you declare inline. The `i18n!` macro generates a typed
`Locale` enum and one function per message; a missing translation or a
typo'd `{placeholder}` is a **compile error**, not a runtime surprise.
Switching language re-renders affected text **in place** — it rides the
same reactive machinery as `text()`, so there's no manual refresh and no
per-platform code.

This is the SDK to reach for whenever a task mentions locale, language,
translation, a language switcher, or multi-language / localized copy —
don't hand-roll a `match` on a language signal.

## 1. Add the dependency

```toml
[dependencies]
i18n = { workspace = true }

# Only if you use opt-in (network-loaded) locales:
# i18n = { workspace = true, features = ["lazy-fetch"] }
```

## 2. Declare your messages

Put the catalog in its own module — `t` is the conventional name — so call
sites read as `t::greeting(...)`:

```rust
pub mod t {
    i18n::i18n! {
        // Exactly one locale must be `(default)` — the reference locale
        // and the fallback when a translation is unavailable.
        locales: { En = "en" (default), Fr = "fr", Es = "es" }

        // A message with a typed interpolation argument.
        greeting(name) {
            En: "Hello, {name}",
            Fr: "Bonjour, {name}",
            Es: "Hola, {name}",
        }

        // A message with no arguments.
        tagline {
            En: "Type-safe i18n.",
            Fr: "Internationalisation typée.",
            Es: "i18n con tipado seguro.",
        }

        items(count) {
            En: "{count} items in your cart",
            Fr: "{count} articles dans votre panier",
            Es: "{count} artículos en tu carrito",
        }
    }
}
```

## 3. Use messages in components

Each message is a function returning `Reactive<String>`. Pass it straight
to any reactive-text prop (`text(...)`, idea-ui's `Typography`, `Button`, …):

```rust
ui! {
    view {
        Typography(content = t::greeting("Ada"))   // "Hello, Ada"
        Typography(content = t::tagline())
        Typography(content = t::items(3))          // "3 items in your cart"
    }
}
```

> **Arguments are snapshots.** `t::items(count)` captures the value at call
> time; the returned text re-renders when the **locale** changes, not when
> `count` changes. For a value that also changes, re-call the message in a
> reactive scope: `Typography(content = rx!(t::items(n.get()).get()))`.

## 4. Switch language (the live-switcher loop)

The macro generates a typed `set_locale` / `current_locale` / a `Locale`
enum. Wire `set_locale` to a control and every visible message updates in
place — no manual refresh:

```rust
use std::rc::Rc;

let pick_es: Rc<dyn Fn()> = Rc::new(|| t::set_locale(t::Locale::Es));

ui! {
    Button(label = "Español", on_click = pick_es)
}
```

`i18n::set_locale_code("es")` is the untyped equivalent (handy when the
code is a runtime string, e.g. from a `Select`). `t::current_locale()` /
`i18n::current_locale_code()` read the active locale. That's the whole loop
for bundled languages — no loaders, works offline on every backend.

## Adding a new language

1. Add the locale to the header: `De = "de"`.
2. Add a `De: "…"` line to **every** message. Miss one and the compiler
   names it: `message 'greeting' is missing a translation for bundled
   locale 'De'`. You can't ship a half-translated bundled language by
   accident.

## What the compiler checks

Each is a `compile_error!` spanned at the offending line:

| Mistake | Error |
| --- | --- |
| Bundled locale missing a message | `message '…' is missing a translation for bundled locale '…'` |
| Placeholder with no matching arg (`{nmae}`) | `placeholder '{nmae}' has no matching argument` |
| Declared arg never used in the default translation | `argument '…' is never used in the default translation` |
| Inline translation for a `lazy` locale | `'…' is a lazy locale; its strings come from a fetched pack` |
| Zero or multiple `(default)` locales | `exactly one locale must be marked '(default)'` |

## Interpolation

Arguments are typed (anything `Display`) and substituted by name; `{{` and
`}}` are literal braces:

```rust
items(count) { En: "{count} of {count} — {{literal braces}}" }
// t::items(2)  ->  "2 of 2 — {literal braces}"
```

Built-in formatting is interpolation only. For plurals / gender / ICU,
install a custom formatter once at startup — it receives the template and
the stringified args and returns the final string:

```rust
i18n::install_formatter(|template, args| my_icu_format(template, args));
```

## Opt-in (network-loaded) languages

Bundled locales compile into the binary. A locale marked `(lazy)` carries
**no bytes in the binary** — its strings live in a JSON pack loaded on
demand, keeping rarely-used languages off the critical path / out of the
wasm bundle.

```rust
locales: { En = "en" (default), Fr = "fr", Ja = "ja" (lazy) }
```

A `lazy` locale must **not** have inline `Ja: "…"` lines (compile error).
Ship a flat JSON pack keyed by message name (`locales/ja.json`):

```json
{ "greeting": "こんにちは、{name}", "tagline": "型安全な国際化。" }
```

Install a loader; `set_locale(Locale::Ja)` then fetches it once. On the web
(feature `lazy-fetch`) use the built-in loader — serve the packs at the
given base:

```rust
i18n::set_pack_loader(i18n::net_pack_loader("/locales")); // GET /locales/ja.json
```

On native there's no page origin — pass an absolute base or install packs
from disk. The loader is just `Fn(&str)`; it's handed a code and must
eventually call `i18n::install_pack` / `install_pack_json`. Until a pack
loads, opt-in messages fall back to the default locale; when it arrives the
same reactive text upgrades in place.

## SSR / SSG

Set the locale (and, for opt-in locales, install the pack from a build-time
file) **before** rendering — like setting the viewport before SSR. Loop
locales × routes to emit per-locale static variants:

```rust
for &locale in t::Locale::ALL {
    i18n::set_locale_code(locale.code());
    if locale.is_lazy() {
        i18n::install_pack_json(locale.code(), &read_pack(locale.code()))?;
    }
    let page = backend_ssr::render_path("/", app);
    write(format!("dist/{}/index.html", locale.code()), render_document(&page, None, None));
}
```

## API reference

Generated by `i18n! { … }` (in your `mod t`):

| Item | Description |
| --- | --- |
| `Locale` (enum) | One variant per declared locale. `Copy`/`Eq`/`Hash`. |
| `Locale::code()` / `from_code(&str)` | Code string ↔ variant. |
| `Locale::is_lazy()` | Whether it's an opt-in locale. |
| `Locale::{ALL, BUNDLED, DEFAULT}` | All / bundled-only locales; the default. |
| `set_locale(Locale)` | Switch language (loads the pack for a lazy locale). |
| `current_locale() -> Locale` | The active locale. |
| `init()` | Seed the active locale to `DEFAULT` (call at startup if your default isn't `"en"`). |
| `greeting(..) -> Reactive<String>` | One function per message. |

From the `i18n` crate itself:

| Item | Description |
| --- | --- |
| `set_locale_code(&str)` / `current_locale_code()` | Untyped locale access. |
| `install_pack(code, map)` / `install_pack_json(code, json)` | Install an opt-in pack. |
| `set_pack_loader(Fn(&str))` / `ensure_pack_loaded(code)` | Opt-in loader seam. |
| `net_pack_loader(base)` *(feature `lazy-fetch`)* | Ready-made network loader. |
| `install_formatter(..)` / `clear_formatter()` | Swap in a custom message formatter. |
