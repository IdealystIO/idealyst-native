CLI tooling
CLI toolingOne binary drives the whole lifecycle: scaffold, develop with hot reload, type-check every platform, test against the live app, and ship signed builds. Each target's build pipeline and platform wrapper is the CLI's job — your project stays plain Rust.
Build & runnew / init scaffold a project; dev runs it with hot reload; run builds and launches on a simulator or device; build produces release artifacts per platform. The web release build content-addresses the bundle (one hash in every filename), so it deploys behind immutable caching headers as-is.For a project with a server_bin, dev --web --local runs the full stack — wasm bundle, API server, file watcher — as one command on one port.
idealyst new my-app             # scaffold a cross-platform project
idealyst dev --web              # build + serve + hot reload
idealyst dev --macos            # native window, tied to the CLI's lifetime
idealyst run ios                # build + boot the iOS simulator
idealyst run android            # build + install on emulator or device
idealyst build --web --release  # content-hashed production bundle
Keeping it correctcheck type-checks every configured platform's cfg surface in one run, so an iOS-only compile error surfaces while you're developing on the web. lint catches idiom drift — raw reactive primitives, hand-built elements, non-PascalCase components — and its JSON output wires into rust-analyzer as a check.overrideCommand for inline squiggles.test runs a Robot suite: it launches the app (or attaches to a running one), drives it over the robot relay — find an element, act on it, assert a signal or label — and reports pass/fail. The same suite runs against any platform the app targets.
idealyst check                  # type-check across configured platforms
idealyst lint                   # idiom lints; --format json plugs into rust-analyzer
idealyst test --macos           # run the Robot suite against the live app
Shippingpublish builds a distribution-signed app and, optionally, ships it — .ipa to App Store Connect for iOS; a Mac App Store .pkg or a Developer ID notarized .dmg for macOS. worker runs the project's jobs-queue worker as a dedicated process, the standalone counterpart to the one dev auto-spawns. export packages #[component(external)] components as Web Components (see Extensibility).
idealyst publish ios            # distribution-signed .ipa → App Store Connect
idealyst publish macos          # Mac App Store .pkg or notarized .dmg
idealyst worker                 # run the jobs-queue worker as its own process
idealyst export                 # components → Web Component suite

Project environmentdoctor diagnoses the local toolchain and tells you what's missing per target. configure devcontainer initializes or updates a Dev Container with idealyst-managed sidecar services (Postgres/MySQL, Redis, MinIO) — it owns its own compose file and leaves yours alone. configure vscode sets up the workspace: recommended extensions plus the lint wiring. sync regenerates derived assets like icons and splash screens from their sources.
idealyst doctor                 # diagnose the toolchain (Rust, web, iOS, Android)
idealyst configure devcontainer # Dev Container + managed Postgres/Redis/MinIO
idealyst configure vscode       # editor extensions + rust-analyzer lint wiring
idealyst sync                   # regenerate icons, splash, derived assets
The AI surfaceThe same catalog that documents your project feeds AI tooling. catalog-json prints every component, props schema, primitive, and guide as JSON — the machine-facing entry editor tooling reads. mcp serves that catalog (plus the Robot introspection tools) over the Model Context Protocol on stdio; point Claude Desktop or Claude Code at it as a command server. docs builds and serves a browsable documentation site from the same data.
idealyst mcp                    # framework MCP server on stdio
idealyst catalog-json           # machine-readable component catalog
idealyst docs                   # catalog-driven docs site for the project
