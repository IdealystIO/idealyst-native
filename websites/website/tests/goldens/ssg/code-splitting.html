Code splitting
Code splittingShip a heavy component as a separate wasm chunk fetched the first time it mounts. Mark the component with #[component(lazy)]; its props cross the chunk boundary, its loading and error props render the in-between states, and native targets compile the body inline.
Lazy componentsAdd lazy to #[component] (or use the #[lazy_component] shorthand). The component's body compiles into a separate wasm chunk; the main bundle keeps a loader stub that fetches the chunk the first time the component mounts. Chunks are fetched once per session and cached — later mounts resolve before the next paint.Chunk files are emitted as module_<n>___lazy_body.wasm; the component's readable name lands in its loader symbol inside __wasm_split.js (__wasm_split_load___idealyst_lazy_Editor_…), which maps any chunk in the network tab back to its component.
use runtime_core::{component, ui, Element};

/// The whole subtree — and every dependency only it
/// reaches — ships in a separate chunk.
#[component(lazy)]
fn Editor(document_id: u32) -> Element {
    ui! { view { /* heavy editor UI */ } }
}

// The call site is a normal component tag:
ui! {
    Editor(document_id = 42)
}
Props cross the boundaryThe component's props are the data that crosses the split: the loader carries them into the chunk and the body receives them as ordinary parameters. Runtime input — a document id, a route param, a config struct — is just a prop, typed and compile-checked at the call site.Signals and callbacks created inside the body work as usual: the chunk's construction runs under its own reactive scope, owned and torn down with the component.
Loading and error UIEvery lazy component gains two generated props. loading renders while the chunk fetches; error renders if the fetch or link fails, receiving a LazyError with .message() and a .retry() handle.retry() re-invokes the loader, which re-passes the props — so it requires them to be Clone. #[component(lazy, retryable)] opts in and derives the bound; the default moves the props into the loader once.
ui! {
    Editor(
        document_id = 42,
        loading = || ui! { Skeleton() },
        error = |e| ui! {
            view {
                text { format!("Couldn't load: {}", e.message()) }
                Button(label = "Retry", on_press = e.retry())
            }
        },
    )
}

// retry() re-runs the loader with the same props — opt in:
#[component(lazy, retryable)]
fn Editor(document_id: u32) -> Element { /* … */ }
How the split worksThe attribute wraps the body in a #[wasm_split] async function. A release web build (idealyst build --web --release) runs the wasm-split pass after wasm-bindgen: it walks the call graph, moves code reachable only through the split function into a chunk wasm, and emits the loader glue that fetches and links the chunk against the live main instance.Chunk-only code leaves the main bundle automatically. Chunk-only static data follows under the experimental --data-prune flag; verify the app still renders when enabling it.
Native and SSROn iOS, Android, macOS, and the GPU backend there is one binary and no network fetch: the attribute compiles the body inline, the loader resolves synchronously, and the loading UI is never visible. The author surface is identical across targets.Server-side rendering emits the loading UI as its output; the client hydrates it and then loads the chunk. Content that must be prerendered belongs outside a lazy boundary.
Heavy SDKsAn SDK renders through a mount handler registered on the scene registry. Registering at boot anchors that handler — and everything it reaches — in the main bundle, wherever the rendering happens. Splitting such an SDK means registering from inside the chunk instead: the app declares the payload kind late-bound with Registry::defer, and the SDK's register_from_chunk() queues the real handler through defer_registration.The framework drains queued registrations at the start of every realization, so the handler is in place before the chunk's own subtree mounts. A payload that already rendered elsewhere in the tree waits behind a layout-transparent placeholder and completes in place when the handler lands — same position, no remount. Declaring the kind is what licenses that wait: a payload nobody declared still fails loudly at realize.
// Boot seam: declare the payload kind late-bound. This costs
// the main bundle a TypeId and nothing else.
pub fn register_scene_extensions<H: Host>(r: &mut Registry<H>) {
    r.defer::<CanvasProps>();
}

#[component(lazy)]
fn CanvasCorner() -> Element {
    // The handler ships with the chunk, not the main bundle.
    canvas_sdk::register_from_chunk();
    canvas_sdk::widget()
}
The lazy! block (deprecated)Earlier versions exposed lazy! { … }, an anonymous block form of the same split. It is deprecated in favor of lazy components: the block form accepts no input across the boundary (the hoisted function is a plain fn, so the block can't reference enclosing variables) and names its chunks by content hash. Existing lazy! blocks keep compiling and splitting; the compiler warning points at the replacement.Migrating is mechanical: hoist the block's body into a #[component(lazy)] fn, turn anything the block couldn't capture into props, and move .placeholder(…) to the loading prop at the call site.
