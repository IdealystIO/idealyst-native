idea-uiThe first-party component library: forty-plus themed components — buttons, forms, tables, overlays, navigation chrome — built entirely on the same public primitives and stylesheet system available to any crate. The page you're reading is composed from it.
Built on public primitivesidea-ui components are ordinary #[component] functions composing view / text / text_input and the rest through ui!, styled with stylesheet! against the theme's tokens. There is no private API underneath them — everything the library does, your components and your own component library can do the same way.Because they lower to primitives, every component renders natively on every backend: the same Card is real views on iOS, AppKit on macOS, DOM on the web, and draws through the GPU renderer on a bare surface.
use idea_ui::{Button, Card, Field, Stack, StackGap, Typography};

let email = signal(String::new());

ui! {
    Card() {
        Stack(gap = StackGap::Md) {
            Typography(content = "Sign in".to_string(), kind = typography_kind::H3)
            Field(
                label = Some("Email".to_string()),
                value = email,
                on_change = move |v| email.set(v),
            )
            Button(label = "Continue".to_string(), on_click = submit)
        }
    }
}
What shipsLayout & surfaces: Stack, Grid, Center, Card, Surface, Divider, Spacer. Forms: Field, Textarea, Select, Autocomplete, Checkbox, Radio, Switch, Slider, SegmentedControl. Overlays: Modal, Popover, Tooltip, Toast, Menu. Data & feedback: Table, List, Tabs, Pagination, Breadcrumbs, Badge, Chip, Tag, Avatar, Alert, Progress, Skeleton, Spinner, Collapsible. Plus Typography, Icon (with the Lucide set), Image, and Link.Interactive components carry the details you'd otherwise build twice: keyboard focus rings drawn from the theme's focus token, hover/press states on every backend, and per-slot style override props when a design needs to reach inside.
The layer underneath → Primitives
ThemingEvery color, radius, spacing step, and type size in the library resolves through named theme tokens. Install a theme once and the whole library follows it; swap themes at runtime and every mounted component re-resolves — including on native backends, where there is no CSS cascade doing the work.App styles join the same system: reference a token by name in your own stylesheet! and your custom components track theme swaps exactly like the library's. This site's dark-mode toggle is that mechanism.
// Install a theme at startup — components resolve tokens from it:
install_idea_theme(light_theme());

// Swap at runtime; every styled node re-resolves reactively:
set_theme(dark_theme());

// Your own sheets can reference the same tokens by name:
stylesheet! {
    Panel {
        background: theme_color!("color-surface"),
        border_color: theme_color!("color-border"),
    }
}
